# Codex 額度狀態列 App 設計

## 意圖

讓 macOS 使用者不用切換視窗，就能在狀態列查看 Codex 目前 5 小時額度的剩餘比例；點擊後可查看完整額度與重設資訊。設計依據為 [codex-reset-checker](https://github.com/doggy8088/codex-reset-checker) 對本機 Codex 登入資料及使用額度回應的處理方式。

## 目標

- 建立原生 macOS 狀態列 app，不顯示 Dock 圖示。
- 狀態列以單行 `82% 2:14` 顯示 5 小時主要視窗剩餘比例與重設倒數，不加 `5h` 標籤；只有 `primary_window.limit_window_seconds` 等於 `18,000` 時才視為 5 小時視窗。資料缺漏時分別顯示 `--%` 與 `--:--`，不可從其他資料推算。
- 點擊狀態列項目後，顯示 5 小時、每週及 API 提供的模型專用額度，並列出各視窗的重設倒數。
- 詳細面板顯示可用手動重置額度數量，以及每筆額度的狀態、取得時間與到期時間；也顯示最後更新時間。
- 啟動時立即查詢，每 60 秒自動更新，並在面板提供立即刷新。
- 使用者可在 API 部分失敗時看出哪些資料不可用，以及資料最後更新時間。

## 非目標與反目標

- 不執行或提供消耗手動重置額度的操作。
- 不保存歷史用量、登入憑證或查詢快取至磁碟；不加入遙測、資料庫、背景服務或 Node.js 執行期依賴。
- 不輸出或顯示 access token、account ID、原始授權標頭或未過濾的錯誤內容。
- 不建立 App Store 發佈、登入流程、用量圖表或額度通知功能。

## 約束

- 平台與 UI：macOS 原生 SwiftUI，使用 `MenuBarExtra` 作為狀態列入口與彈出面板；app 以背景狀態列 app 方式啟動，不建立一般 Dock 視窗。
- 認證：讀取 `~/.codex/auth.json` 的 `tokens.access_token`，以及存在時的 `tokens.account_id`。缺少或格式錯誤時顯示可理解的錯誤與重新登入提示；不複製、修改或刪除此檔案。
- 查詢：唯讀呼叫參考工具目前使用的 `GET /backend-api/wham/usage` 與 `GET /backend-api/wham/rate-limit-reset-credits`。以 `Authorization: Bearer …`、`OpenAI-Beta: codex-1`、`originator: Codex Desktop` 傳送必要標頭；有 account ID 時才加上 `ChatGPT-Account-ID`。
- 介面：以 `primary_window.used_percent` 計算剩餘百分比（100 減已使用百分比）；只有視窗時長明確為 `18,000` 秒時，才把它標為 5 小時視窗。使用 API 提供的重設秒數或重設時間顯示倒數。缺少或無效欄位顯示為不可用，不以預設額度補值。額外額度只呈現 API 實際回傳的項目。
- 更新：啟動即查詢、每 60 秒刷新、面板有手動刷新；同一時間不得重疊發出重複刷新。結果只保留在記憶體供目前畫面顯示。
- 私有介面限制：上述 `/wham` 是參考專案標示的 ChatGPT 非公開後端介面，服務端可能改動欄位或拒絕請求。錯誤須安全呈現，部分端點失敗不可令其他已成功資料消失。

## 考慮過的做法

1. **原生 SwiftUI 直接查詢（採用）**：狀態列與額度面板使用原生元件，直接讀取 Codex 登入檔並呼叫唯讀 API。符合常駐狀態列與快速查看需求，也不要求額外執行期。
2. **包裝現有 Node.js CLI**：可以重用 CLI 的解析程式，但部署還需處理 Node/npm、子程序生命週期與 JSON 傳遞，對個人 macOS 狀態列 app 增加不必要的執行環境。

## 使用流程與畫面

```text
狀態列：  82% 2:14
              │ 點擊
              ▼
┌──────────────────────────────┐
│ Codex 額度          [立即刷新] │
│ 5 小時視窗           剩餘 82%  │
│ 重設倒數              2h 14m   │
│ 每週視窗              剩餘 64% │
│ GPT-5.3-Codex-Spark     剩餘 … │
│ 手動重置額度           2 筆    │
│   狀態 / 取得時間 / 到期時間   │
│ 最後更新              14:05   │
└──────────────────────────────┘
```

畫面需有載入、成功、部分失敗、完全失敗及缺少登入檔狀態。使用額度與手動重置額度各自保存記憶體內的最後成功時間；其中一個端點刷新失敗時，保留該區上次成功資料並標示該區錯誤及時間，另一區仍可更新。首次失敗時顯示錯誤，不假裝有剩餘比例。顏色只能輔助資訊，所有額度均需有文字標籤。

## 實作責任

- 認證讀取器：安全解析預設 auth.json，只回傳建立請求所需的記憶體憑證。
- API client：封裝標頭、逾時、並行讀取 usage 與 reset credits，並對錯誤訊息做敏感資料過濾。
- 回應正規化：將已使用百分比、重設資訊、額度項目與信用額度欄位轉成 UI 使用的明確型別；未知欄位不得洩漏到 UI 或日誌。
- View model：管理初次載入、60 秒計時、手動刷新、部分錯誤、最後成功時間及畫面快取。
- SwiftUI 狀態列與面板：呈現簡短狀態及完整唯讀明細。

## 完成條件

- 啟動 app 後狀態列會顯示 5 小時額度剩餘比例，無法取得時顯示未知狀態。
- 點擊狀態列項目會看到 5 小時、每週、可用模型額度、重設倒數及手動重置額度明細。
- 啟動、定時與手動刷新均更新畫面；錯誤和部分資料缺失不會顯示誤導數值。
- 查詢流程不會修改本機 Codex 憑證檔或消耗手動重置額度，且不會記錄敏感憑證。
